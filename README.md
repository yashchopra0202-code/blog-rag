# blog-rag

RAG over recent AI-lab blog posts. Ask questions from a web page.

## Setup
1. `python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt`
2. `cp .env.example .env` and fill in `ANTHROPIC_API_KEY` and `VOYAGE_API_KEY`.
3. `scrapling` must be available at `~/.venvs/scrapling` (see the scrapling skill).

## Run (in order)
1. Scrape:    `~/.venvs/scrapling/bin/python scraper.py`   # writes data/articles/*.md (incremental)
2. Nuggetize: `.venv/bin/python nuggetize.py`              # summarizes new articles into data/manifest.json
3. Index:     `.venv/bin/python ingest.py`                 # builds chroma_db/ (needed for /ask; skip if you only want the feed/digest)
4. Digest:    `.venv/bin/python digest.py`                 # emails new nuggets via Resend
5. Serve:     `.venv/bin/uvicorn api:app` then open http://127.0.0.1:8000

Re-run the scraper any time to pick up new posts, then re-run nuggetize/ingest/digest as needed.

## Daily nuggets

A "nugget" is a 2-3 sentence LLM summary of one article (what happened, why it matters), generated by `nuggetize.py` and stored on that article's entry in `data/manifest.json` (fields: `nugget`, `nugget_at`). Nuggets are cheap to skim without loading the full RAG index.

- **`GET /feed?days=7`** returns nuggets from the last N days, grouped by scrape date, read straight from the manifest (no vector index required). The **Today** view on the web page (`/`) renders this feed.
- **Email digest**: `digest.py` selects manifest entries with a nugget that are newer than the last run (tracked in `data/digest_state.json`) and emails them via [Resend](https://resend.com). Required env vars: `RESEND_API_KEY`, `DIGEST_TO`; optional `DIGEST_FROM` (defaults to `onboarding@resend.dev`). See `.env.example`.
- **GitHub Actions**: `.github/workflows/daily.yml` runs on a daily cron (`0 13 * * *`, 13:00 UTC) and can also be triggered manually (`workflow_dispatch`). It runs scrape → nuggetize → digest, then commits the refreshed `data/articles/`, `data/manifest.json`, and `data/digest_state.json` back to the repo. Required repo secrets: `ANTHROPIC_API_KEY`, `RESEND_API_KEY`, `DIGEST_TO`, `DIGEST_FROM`.
  - **CI does not build the vector index.** The workflow intentionally skips `ingest.py` and never touches `chroma_db/` (a binary sqlite file, not something you want in git history). To use `/ask` locally, run `.venv/bin/python ingest.py` yourself after pulling the latest data.
  - Live validation of the scheduled workflow (does scraping work from a CI IP without hitting bot walls, does the email arrive, does the commit-back push cleanly) is deferred until this repo has a GitHub remote and secrets configured — untested as of this task.

## Tests
- RAG venv:      `.venv/bin/python -m pytest tests/test_article_format.py tests/test_sites.py tests/test_rag_core.py tests/test_api.py`
- Scraper venv:  `~/.venvs/scrapling/bin/python -m pytest tests/test_scraper.py tests/test_extraction.py`

## Security
The `/ask` endpoint feeds raw scraped third-party article text to the LLM as context, so it implicitly trusts the content of the configured blogs. This is acceptable for a local personal tool over trusted lab sources, but it means you should only add sites you trust to `sites.py`.
