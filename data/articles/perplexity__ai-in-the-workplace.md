Learn how to use AI in the workplace for 10 recurring tasks, with ready-to-use prompts, safety tips, and a simple pilot.

Contents

This article breaks down how knowledge workers can use AI on the recurring tasks that eat time every week, not just for one-off questions and writing tasks. It includes ready-to-use prompts, guidance for using AI safely, and steps for building AI into your workflows quickly and simply.

Most knowledge work comes with operational overhead that isn't in the job description: meetings, admin, staying informed, managing relationships.

These tasks are often the best place to start using AI, because the output is easy to check and the stakes of getting it wrong are low.

Below are 10 of those tasks, and how to prompt AI to help with each.

Note: Some AI tools need source material attached or pasted directly. Others can pull it themselves from a connected inbox, drive, or open browser tabs. The prompts below work either way.

Most knowledge workers already use AI casually: a one-off question, a quick email draft, copy the result, done. Treating a task as a two-week pilot, not a one-time question, is what turns that casual use into meaningful time savings.

Here’s how to start:

For five working days, log every repetitive task, how long it takes, and how tedious it feels. There are multiple time-tracking tools available, but a running note works fine: "Monday, 20 min, sorted receipts, mildly annoying." By Friday, a pattern usually stands out on its own.

Review the notes and choose which time-consuming, tedious task to automate first.

There are a few factors to consider:

A weekly status update or a recurring expense report fits. A once-a-quarter board deck doesn't. The stakes and the review time are both too high for a first pilot.

Write a sentence describing a correct or usable output, decided before seeing what the AI produces.

Pull three real examples of the output done manually (three status updates, three expense reports), and write down what they have in common: length, structure, level of detail.

Then ask what would make it unusable. Sometimes it's easier to define good by naming the failure. Include the opposite of each failure in the definition of a good output.

For example, for a status update, that might be: "Covers what shipped and what's blocked, in two paragraphs, with minimal rewriting needed."

For an expense report, it might be: "Every line has a category, and duplicates are flagged."

Start with a plain description of the task and the "good" definition from step 3, then run it against two or three real instances.

After each run, compare the output against that definition and note what's off: missing a section, too long, wrong tone. Add a line to the prompt addressing that specific gap, then run it again.

Stop once the output needs only minor editing, not rewriting. Save the final version somewhere easy to find again: a pinned doc, a notes app, or a shared prompt library, for instance.

Pick one repeatable thing to verify manually. For an expense report, that might mean comparing the category totals against the raw export before submitting it. Do that same check on every output for two weeks, even once it starts to feel reliable.

For each instance, track how long the task took start to finish, including the check step, and how it compares to the time logged in step 1. At the end of two weeks, add it up to decide whether it’s worth keeping the automation as is. If not, adjust and retry, or drop it and pick a different task.

Pick the task that eats the most time and shows up most consistently, run it through the pilot steps, and note how much time or effort AI saves.

It's the use of AI tools, like connected assistants and chatbots, to help with the recurring parts of a job: staying informed, communicating, planning, reviewing, and administrative work, in addition to the one-off questions most people already ask.

Pulling action items out of a meeting transcript, turning raw notes into a status update, categorizing an expense report, building a source-backed presentation outline, and prepping for a call using past context are five common ones.

The clearest benefit is time back on tasks that follow a predictable pattern: summarizing, drafting, categorizing, and reviewing work that takes real time to do by hand but doesn't require deep judgment.

The upside is faster first drafts and less time on repetitive tasks. The downside shows up when the check step gets skipped: an unverified summary treated as fact, a draft sent without review, or sensitive data pasted into a tool that was never approved for it.

Start with one recurring task, track how it's currently done for a week, define what a good output looks like, test a prompt against a few real instances, and set one fixed check to run on every output during a two-week pilot.

The main risks are treating AI output as verified when it isn't, sending sensitive data through an unapproved tool, and letting an AI summary substitute for a decision, an approval, or a relationship judgment that still needs a person.

For most knowledge work, AI is replacing specific repetitive tasks inside a role rather than the role itself. The tasks in this guide, communication, admin, first drafts, are the ones most likely to shift, while judgment, accountability, and relationship-building stay with the person doing the job.
