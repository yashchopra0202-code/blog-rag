Portable Computer runs on AMD Ryzen AI Max systems. Run local AI tasks and recurring workflows without spending credits.

Contents

People want to put their own compute to work on more of their everyday tasks, from analyzing local files to running recurring workflows. Completing that work on their own hardware gives them more control over sensitive information and credit spend. To let more people work this way, local AI needs to run on more devices and connect to the tools they already use.

Today we’re expanding

to systems powered by AMD Ryzen AI Max Series processors including the Ryzen AI Halo developer platform, giving more people a way to run local AI on their own hardware.

Local inference doesn’t consume Computer credits. Users can run routine analysis and file processing on their Ryzen AI Max-powered system. The local model can still escalate to the cloud for more advanced research and reasoning when needed.

AMD support gives users another way to run Perplexity Computer locally. They can put their own hardware to work on demanding tasks while limiting credit spend.

People have work they could give to an agent if sensitive files, such as deal documents, patient records, unreleased code, and payroll exports, could stay on device. That requires a local model, tools to work with those files, and controls over what the agent can access.

Portable brings the local model, agent harness and orchestrator, scheduler, sandbox, and sensitive-content classifier to one system. Available models include Qwen 3.8 27B and PPLX 27B, Perplexity’s post-trained model. Users no longer have to assemble the stack themselves by setting up an inference server, connecting an agent, and configuring each tool.

AMD and Perplexity are making it easier for developers to get started with local agents on Ryzen AI Halo. Users can download a model in one click through Local Inference in the Perplexity app’s settings. The inference engine and classifier install with it. Users then connect their apps and choose the folders Portable can work in.

A task that starts with local files may still need current information or more advanced reasoning. A financial analyst working with a local earnings model, for example, might use current market data from the web and frontier-model reasoning to test how changing interest rates could affect their forecast.

Portable gives users access to cited web results through Perplexity Search and advanced reasoning from 15+ frontier models. If a task needs to send information from the device to the cloud, Portable asks for the user’s permission before moving forward.

Portable works across local files and connected apps. Its local orchestrator connects to Gmail, Outlook, Slack, and GitHub. Local Model Context Protocol (MCP) servers let it work with supported applications installed on the same PC.

Recurring work uses the same local model, so its local inference doesn’t add to Computer credit spend with each run. Scheduled tasks run while the app is open and the PC is awake.

An agent that writes and runs code needs clear boundaries. Portable runs code and tools inside an isolated on-device sandbox, with read and write access limited to permitted folders. It reaches connected apps only through connectors the user has configured.

An on-device classifier scans content for sensitive details, such as names, account numbers, and credentials, before it leaves the PC. If it flags sensitive information, the user can choose to share it, keep that step on the local model, or stop.

Organizations can control access to inference on managed accounts. An administrator decides whether it is allowed, so IT can make it available to the teams that need it.
